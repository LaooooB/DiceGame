# 工程结构与扩展位置

`Core` 完全不引用 Godot。它负责游戏真状态；`Presentation` 只消费状态和事件；`GameApp` 处理玩家操作和场景转换；`GameRoot` 负责引擎连接。可脱离图形设备测试战斗。

修改伤害、装填、点数成长、波次增长：先看 `Data`。类型注册统一由 `GameData` 读取。添加既有行为类型的骰子可以复用配置；新增行为需要在模拟的明确效果分支扩展，同时补参考或独立测试，不把业务写到绘制函数中。

`Simulation.Step` 的处理顺序对战斗结果有影响，不能单纯为了“更像 Godot”换成多个节点各自 `_PhysicsProcess`。在效果完全一致验收完成前，暂不替换碰撞算法、不并行重排命中和连锁、不修改随机源。

UI 命中由 `UiLayout` 生成，与渲染帧是否已发生无关，避免一帧滞后的按钮区域。鼠标坐标只在 `GameRoot` 从窗口转换到 432×864 逻辑坐标一次。界面尺寸改变不修改战斗数据。

声音、存储通过接口接入；纯 C# 测试中使用空声音实现和内存存档。数据保存采用快照，避免保存后的数据继续被游戏状态引用污染。

`NativeCanvas` 负责原生绘图适配：图集、文本、渐变、线段、圆、多边形。它不是 JS 解释器。Tests/Original 内的 JS 仅供离线对照工具运行，发行包明确排除。

所有引擎节点在 `GameRoot` 初始化，可在远程场景树查看：`DesktopSurround`、`BattlefieldViewport`、`GameCanvasViewport`、`DesktopGameFrame`、`SynthesizedAudio`。当前并未把每个粒子/弹丸拆成单独场景，因为那会引入新的调度和状态管理；独立编辑器场景不是本次效果迁移的必要条件。
