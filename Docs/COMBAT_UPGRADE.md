# 24 格与骰子分支：实现、计算与配置

本次基于 `DiceGame-Godot-Campaign-Complete.zip` 修改。本文是当前规则，不是之前八格工程的说明。配置与实现均在交付工程内；没有改写远端 GitHub。

## 1. 玩家规则

阵地 24 格，6 列 × 4 行；卡组恰好六种不同且已解锁的骰子。必须同种类、同点数且未满六点才能合成。合成结果仍从本局六骰卡组均匀随机抽取，结果身份与随机状态先确定，选技能不能重抽。

三级（3 点）选择新结果种类的 A 或 B。四、五级保留落点材料骰子的 A/B 字母，并映射为新种类自己的技能；不会把爆破的范围爆炸技能带到冰霜骰子上。这是合成后种类随机情况下的明确继承规则，不在四、五级额外打断战斗。

六级（6 点）清除旧分支：先为最终种类重新选择 A/B，再选择它的 C/D。先选 A 不意味着第六级必定配 C；四种 A+C、A+D、B+C、B+D 均允许。分支属于具体骰子实例，同种骰子可有不同分支，不修改全体同类骰子。

例：两颗五点爆破合成随机得到六点冰霜，界面先提供冰霜 A/B，确认后提供冰霜 C/D；不会出现爆破技能，不保留旧爆破分支。

选择界面暂停敌人、弹丸、装填、能量恢复和波次推进；不允许同时召唤、合成、移动或发射。只有本次必要选择全部确认后才发出合成齐射，齐射使用新技能快照。此前已发射的弹丸保持自己的快照，不被后续选择追溯修改。普通波次三选一强化保留，与骰子分支分开处理。

## 2. 为什么选择 24 格

六点骰子需要 32 个一点骰子的合成质量，但不要求 32 个骰子同时占格。空间压力来自“六种种类 × 五种未满点等级”造成的不可配对残留。

容量实验使用固定种子 **20260915**，每种开局各 **20,000 次**。每次优先合成最低点数、同点数按种类顺序选择的可合成对；没有对子才召唤。召唤种类和合成结果都是六种等概率；第一次得到六点时停止。记录该路径所需的峰值占格数。下表用旧三骰开场隔离格子容量这一变量：

| 格子 | 首个六点前无需回收的次数 | 样本比例 |
|---:|---:|---:|
| 8 | 0 / 20,000 | 0.000% |
| 12 | 41 / 20,000 | 0.205% |
| 16 | 2,860 / 20,000 | 14.300% |
| 18 | 8,578 / 20,000 | 42.890% |
| 20 | 15,139 / 20,000 | 75.695% |
| 22 | 18,812 / 20,000 | 94.060% |
| 24 | 19,857 / 20,000 | 99.285% |
| 26 | 19,997 / 20,000 | 99.985% |
| 28 | 20,000 / 20,000 | 100.000% |
| 31 | 20,000 / 20,000 | 100.000% |

旧三骰开场的平均峰值约 **18.92 格**，99 分位 **24 格**。20 格仍有约 24.3% 的试验需要先回收才能继续；24 格降为 **0.715%**。再用实际新九骰开局独立重跑：24 格成功 **99.355%**，需回收比例 **0.645%**。

因此采用 24，而不是简单从 8 加到 12/16；也没有加到足够宽松的 31 格来移除大部分空间取舍。未有六点骰子时，最多有 30 个种类/点数桶，每桶最多一个才无对子，因此 31 格是这个模型下避免首次六点前容量死锁的一个充分上界，24 格不是数学保证。

**这不是胜率或整局不卡满概率。** 实验没有敌人、能量限制、玩家犹豫、保留成型六点骰子、主动保留低级火力等因素；也没有把 20,000 次中的零成功解释成绝对不可能。满格时仍允许回收，界面明确提醒如何腾位。要验证真人节奏，需要进一步实战与遥测，不能用这个容量模型替代。

复现：

```sh
python Tools/analyze_board_capacity.py --trials 20000 --seed 20260915
```

输出 `Artifacts/board-capacity.json`，包含两个开局方案的统计、直方图和限制说明。

## 3. 伤害与经济补偿

| 项目 | 之前 | 当前 | 理由 |
|---|---:|---:|---|
| 阵地格子 | 8 | 24 | 降低六种随机合成的容量卡满 |
| 单骰基础伤害系数 | 1 | 1/3 | 相同点数/种类组成下，满场基础直接火力预算不变 |
| 开场骰子 | 3 | 9 | 抵消前期单骰减伤，保持相同组成下开局直接火力 |
| 召唤能量 | 24 | 8 | 同样能量可买三倍单位，不让扩容后的空位长期无法利用 |
| 回收返还 | 8/14/25/45/81/146 | 3/5/8/15/27/49 | 按约 1/3 调整，保留整数返还 |
| 活跃弹丸上限 | 420 | 840 | 给扩容和分裂分支留空间，但仍有硬预算 |
| 待发弹丸上限 | 600 | 1200 | 覆盖连射/分裂与合成齐射，仍拒绝无界队列 |

基础伤害使用 `Data/game.json → rules.damageScale` 统一乘一次，避免每个技能单独漏削。`Data/dice.json` 的基础种类差异和等级曲线保留；范围、连锁、子弹伤害等基于已缩放的弹丸伤害继续计算，不额外再乘 1/3。

满场同质基础输出：`24 × (原单骰输出 / 3) = 8 × 原单骰输出`。开局为原模式 `[主骰, 主骰, 第二骰]` 重复三次，同样只在基础直接输出意义上持平。新增技能、命中率、反弹次数、控制、过量伤害、局外加成都能改变实际战果，不宣称最终难度精确不变。

增加弹丸数的技能重新分配一轮总伤害：`单弹伤害 = 本轮直接总伤害 / 弹丸数量`，避免“弹丸多了且每颗仍保留整轮伤害”的重复放大。子弹本身的寿命、穿透、反弹次数和连锁条数也有上限；满队列的合成在消耗材料和随机数之前被拒绝。

## 4. 当前 24 个技能

名称、说明和修正值都在 `Data/dice_skills.json`。A/B 对应三级，C/D 对应六级，下面为当前配置正文。

### 速射 · `pulse`

- **A · 重弹**：齐射伤害 +30%，装填时间 +10%。少量重弹更适合稳定命中。
- **B · 连射**：每轮多发 2 颗弹丸；总齐射伤害 +12%，装填时间 -10%。伤害均分到全部弹丸。
- **C · 穿阵**：每颗弹丸前 2 次命中穿透敌人而不反弹；穿透不消耗反弹次数。
- **D · 猎首**：对头目的直接命中伤害 +50%。

### 爆破 · `blast`

- **A · 广域爆破**：爆炸半径 +35%，溅射系数 -15%。覆盖更分散的敌群。
- **B · 聚能爆破**：爆炸半径 -20%，溅射系数 +40%，齐射伤害 +8%。
- **C · 殉爆**：直接命中击杀敌人时，追加一次相当于该弹丸伤害 45% 的范围爆炸；追加爆炸不会再触发殉爆。
- **D · 破城弹**：对头目的直接命中伤害 +50%，基础爆炸溅射系数 +15%。

### 雷电 · `arc`

- **A · 分流**：连锁目标 +2，每次连锁伤害系数 -15%。
- **B · 远距电弧**：连锁距离 +40%，连锁伤害系数 +25%，连锁目标 -1（至少 1 个）。
- **C · 回流**：没有找到目标的每一跳，将 20% 弹丸伤害返还给最初命中的敌人；不会生成新电弧。
- **D · 霜雷共振**：直接命中和连锁对已减速目标造成的伤害 +45%。与冰霜骰子配合。

### 冰霜 · `frost`

- **A · 深寒**：减速后的移动速度降为原速的 38%，持续时间 -10%。头目仍保留至少 72% 移速。
- **B · 冻雾**：减速传播到半径 34 内的敌人；持续时间 +50%，减速后的移动速度为原速的 62%。
- **C · 碎冰**：命中已减速的敌人时，直接伤害 +35%，并对半径 40 内的其他敌人造成 30% 弹丸伤害。
- **D · 寒潮**：减速传播半径至少为 64，持续时间 +25%。扩散不会触发额外命中或伤害。

### 分裂 · `split`

- **A · 繁星**：分裂子弹 +2，每颗子弹的伤害系数 -20%。子弹仍不递归分裂。
- **B · 重型碎片**：分裂子弹 -1（至少 1 颗），子弹伤害系数 +60%，子弹寿命 +0.8 秒。
- **C · 穿透碎片**：分裂子弹获得 2 次穿透；母弹不获得穿透。
- **D · 回旋碎片**：分裂子弹反弹上限 +4，寿命 +1.5 秒，伤害系数 +15%。

### 回弹 · `bank`

- **A · 强折射**：每次撞墙增伤增量 +40%，撞墙增伤上限 +0.4。
- **B · 长线蓄能**：反弹上限 +4，撞墙增伤上限 +1.0，每次撞墙增伤增量 -15%。
- **C · 余辉**：命中后保留本次撞墙额外增伤的 50%，而不是全部归零。
- **D · 震荡折射**：带有撞墙增伤时命中，对半径 48 内其他敌人造成“本次撞墙额外伤害”的 45%。不递归触发。

## 5. 强制六种与局外成长的衔接

旧新档只开放两种骰子，与强制六种无法同时成立。当前已有的六种基础骰子全部默认开放，旧档也补齐这六种；未来新增骰子不自动开放，继续走原奖励/建筑解锁接口。

原四个解锁工坊改为对应骰子的永久伤害 +10%。它们仍需要蓝图、消耗资源和完成施工。已完成这些工坊的旧档在版本迁移时补给对应新增成长，保存升级后不会重复补发。其他建筑、区域齿轮、主骰身份和深潜推进没有改成全骰一次通关。

编辑卡组允许临时移除一颗方便替换，但不足六种时不能保存或出发。未来加入第七种骰子后，玩家仍选择其中六种，而不是必须带全部已解锁骰子。配置与运行时校验、界面禁用和开局校验一致。

## 6. 状态、事务和旧档

`DieState.Tier3/Tier6` 只存短分支键。`RunState.SkillSets` 固定本局技能定义，修改目录不悄悄修改已经开始的分支效果。`RunState.PendingSkills` 保存结果实例 ID、结果种类、点数、选择阶段、选择令牌以及待发合成齐射数据。

选择走 `GameApp.Skills`：复制候选模拟 → 校验选择 → 应用效果 → 保存完整候选 → 写盘成功后发布。磁盘失败不吞选择、不提前发齐射、不重新抽骰。旧选择令牌不能被双击拿来消费下一阶段；即使表现事件队列清空，待选状态也会恢复正确界面。

存档内部版本为 3，仍沿用原玩家文件名。版本 1/2 的八格数据先按旧结构校验，再扩至 24 格，保留原位置、骰子实例、点数、主骰、资源和随机状态。旧三至五点骰子补选 A/B；六点补选 A/B、C/D；不会因此赠送合成齐射。旧结算中的高点骰子在选择继续无尽时也先补选。旧弹丸和待发弹丸仍使用保存时快照；新发射按新的统一预算计算。

版本迁移不重置战斗时间、敌人或区域记录。旧无尽的波次流程保留，新伤害和经济属于版本级规则，升级后统一生效。当前新格式中的缺失分支、错实例选择、重复实例、错误骰子种类或不足六种卡组属于损坏数据，不靠静默补齐掩盖。

已有行为的数字、范围和组合可配置。新增真正不同的行为，仍需扩展类型明确的修正字段、命中处理、存档校验和测试；任意写个字符串不会自动生成新技能。未知 JSON 修正字段会报错，不会把拼错的技能悄悄当无效配置。

正常 UI 保持原生 Control。放大字号时右侧说明区可滚动，不把整个窗口挤出屏幕；24 个格子与主操作在 1080p 默认布局中可用。几何布局不参与弹道计算。旧八格菜单/文案只在冻结的开发用对照入口中保留。
