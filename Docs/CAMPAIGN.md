# 城镇—区域远征体系

## 流程与权威

`CampaignState` 保存永久资源、骰子/机制/蓝图、建筑、各层区域记录、最近结算及活动远征标识。`RunState.Expedition` 保存当局区域快照、主骰、奖励随机状态、拾取物、已击败头目和结束原因。`Simulation` 只推进当局；`CampaignProgression` 处理回城规则；`GameApp` 负责操作、保存和页面转换。界面不直接发奖励。

正常入口是城镇。区域选择只允许开放区域；卡组只能用已解锁骰子，最多六种且不能重复。首位骰子作为主骰，只承担通关进度身份，不增加一个角色或强制永久占用棋盘位置。开局保存时固定该身份，局内合成变成别种骰子不会篡改通关身份。

地图不是爬塔岔路图：玩家选择区域，完成该区域的一次有限挑战，回城后再选区域。每个区域有有序阶段和头目边界。当前示例内容是三阶段，每阶段 12 波；头目分别在第 12、24、36 波。波间隔、敌群和成长机会在区域数据中独立配置；不应把这些示例数值误认为参考游戏的精确节奏。

## 区域推进

通关记录按“深潜层 + 区域”保存，记录已完成该区域的不同主骰。一次有效胜利最多增加当前主骰的一份记录。重复使用同一主骰通关不会新增齿轮；六骰卡组也不会一次新增六份。下一地区可同时要求前一区域不同主骰数量、当前层总齿轮、蓝图/建筑/机制等条件。UI 显示未满足的条件。

为新骰子提供试用目标的关系是：前面区域掉落蓝图 → 回城建设解锁骰子 → 更换主骰获得新的通关记录 → 满足后续区域条件。数据目录启动时做引用与可达性检查，避免开门依赖门后的骰子。

达到 `nextCycleRequirements` 才能开始更深一层。永久资源、建筑、骰子、机制保留；新层用独立区域记录和更高难度重新推进。旧层记录不删除。无尽模式另由 `endless` 机制开放：有限区域胜利并成功结算后，可保留当前阵地继续；后续只计算新增物资，不再次发同一有限关卡的胜利奖励。

## 胜败与奖励

头目逃过防线不算击败。小头目不能因超过波次时间而被跳过。最终胜利需要最终头目的真实击败记录以及该波结束条件，不允许仅靠删除敌人/计时判胜。

胜利领取当局物资、蓝图、区域胜利奖励、尚未领取的首通奖励和主骰记录。失败/撤回只领取已实际得到的物资和蓝图，不领胜利奖励或齿轮。零击杀开局撤回不补派遣补给，避免无限开退局刷资源。正常远征有有效击杀后按配置补给城镇派遣，避免用完补给永久卡死。

战斗伤害随机和掉落随机独立，增加蓝图或资源抽取不会打乱原弹射随机序列。掉落蓝图优先避开已持有/本局已获得项目；不存在可抽蓝图时正常继续。

## 建设与成长

城镇是独立弹射模拟，不把原战斗改造成造城。地块来自网格配置；资源地块不可被建筑覆盖。建筑放置/升级支付成本一次，进入施工中；弹射命中推进施工，达到工作量后才授予本级奖励。已完成建筑可搬迁到合法空地，无需重复支付解锁奖励。派遣飞行状态可保存恢复。

奖励由资源增量、骰子 ID、机制 ID、蓝图 ID 和已有的永久战斗增益组成。永久增益汇总后在开局生成快照，不在每帧读取全城建筑。当前通用数值项是伤害百分比、装填缩短、初始能量、被动能量。新增真正的新行为需扩展明确的行为处理器和测试，不是随便写一个新字符串就能自动生成行为。

## 内容扩展

优先改 `Data/campaign.json`：`initialDice`、`initialBlueprints`、`initialResources` 决定新档起点；`regions` 决定顺序、阶段、敌群、条件和奖励；`buildings` 决定成本/施工/每级奖励；`mechanics` 决定机制登记与文案；`town` 决定弹射和资源地块；`nextCycleRequirements` 决定下一层条件。

现有六骰的战斗参数仍在 `Data/dice.json`，点数和基础限制在 `Data/game.json`，局内强化在 `Data/upgrades.json`。新骰子复用已有伤害行为时可以扩展登记；新增伤害行为要同步模拟、快照校验与测试。当前原美术图集只有六种骰子的行，新 ID 的美术须在 `UiKit.SetDice` / `NativeArt` 的映射或新的图标资源接口中补充，不能假定配置 ID 会自动产生美术。

ID 是存档键，发行后不应随意重命名。改名称/说明不改 ID；删除已发布内容需要提供迁移。新局固定区域快照，旧局保存原快照；完成后再使用当前目录开启下一局。

## 保存与异常

存档版本 2 保留版本 1 的读取迁移。新档与旧档区分，旧玩家保留全部原骰子使用权，未结束的原无尽战斗继续按旧规则运行。UI 恢复升级选择、暂停和待结算；不要把读取到结算页当作已经付过奖励。

事务采用候选状态：校验 → 计算 → 序列化 → 磁盘替换 → 发布。磁盘失败不扣永久资源、不确认奖励、不消失蓝图。结算使用活动 GUID、递增远征序号和已结算序号组成防重复记录，崩溃后的重复结算仍只发一次。只支持单玩家本地进程；没有云同步/跨进程写入合并，也不将本地 JSON 当作防作弊安全边界。

`DesktopStorage` 写临时文件并 flush，再替换主档；保留可解码的上一代 `.bak`。均损坏时保护原文件，不建新档覆盖。备份逐文件写盘并检查 SHA256；明确确认重置之后才删除当前档/轮换备份，历史备份目录不会清空。

## UI 与原战斗保留

所有新页面和棋盘交互使用原生 Control，场景模板在 `Scenes/UI`。原战斗以 SubViewport 合成，逻辑坐标与碰撞保持原值；图像坐标缩放不参与伤害/弹道计算。原动态战斗特效保留事件驱动，不用截图替代。

`ReferenceRoot` 只供旧画面对照。正常游戏不会进入旧无限菜单。原有测试不能证明新 UI 与旧竖版画面逐像素相同；新的桌面布局是有意变更，核心战斗一致性由原回放/音频/输入测试验证。
